================================================================================
PROMPT ENGINEERING TECHNIQUES DEMONSTRATED IN THIS PROJECT
================================================================================

1.  ROLE PROMPTING              Assigning an expert persona to condition tone
2.  STRUCTURED OUTPUT           Enforcing rigid labeled output format
3.  NEGATIVE CONSTRAINTS        Explicitly stating what NOT to do
4.  CONTEXT INJECTION           Dynamically inserting variables into prompts
5.  CHAIN-OF-THOUGHT            Requesting step-by-step reasoning
6.  CHAIN-OF-THOUGHT SUPPRESS.  Suppressing reasoning when format matters more
7.  STAR METHOD ENFORCEMENT     Grounding answers in Situation/Task/Action/Result
8.  ADAPTIVE DIFFICULTY         Mapping difficulty levels to natural language
9.  DIVERSITY INJECTION         Passing previous outputs as negative examples
10. FEW-SHOT FORMATTING         Showing the output structure as an implicit example
11. SPECIFICITY PROMPTING       Asking for concrete details not vague generalities
12. MULTI-PART TASK PROMPT      Breaking a complex request into numbered subtasks

PROMPT A-01
Purpose   : Design the overall multi-agent system architecture
Tool used : Claude (Anthropic)
Techniques: Role prompting, Chain-of-thought, Multi-part task prompt
--------------------------------------------------------------------------------

I am building an AI-powered interview simulator for my Generative AI final
project. The system must use a multi-agent architecture where different agents
handle different tasks. Here are the requirements:

1. The system should generate interview questions based on role, difficulty,
   and interview type (HR, Technical, Mixed).
2. It should evaluate candidate answers on 4 dimensions: Clarity, Relevance,
   Depth, and Structure — each scored 1-10.
3. It should generate actionable feedback after each answer including strengths,
   weaknesses, suggestions, and an improved model answer using the STAR method.
4. At the end of the session it should produce a final performance report.
5. The system must run locally using Ollama (no cloud APIs).
6. The backend should be FastAPI and the frontend a single HTML page.

Please design the folder structure, list the agents needed, and explain what
each agent does and why it is a separate component.

WHY THIS PROMPT WORKS:
- Numbered requirements give the model a clear checklist to address
- Mentioning STAR, Ollama, FastAPI up front constrains the solution space
- Asking "why it is a separate component" triggers reasoning about design

PROMPT A-02
Purpose   : Generate the FastAPI backend (main.py)
Tool used : Claude (Anthropic)
Techniques: Multi-part task prompt, Context injection, Specificity prompting
--------------------------------------------------------------------------------

Write a complete FastAPI backend for the AI interview simulator.
It must have these API endpoints:

POST   /api/start               — takes role, interview_type, num_questions;
                                  returns first question
POST   /api/submit              — takes session_id, answer; evaluates and
                                  returns feedback + next question
POST   /api/skip                — skips current question, records it as
                                  skipped with score 0
GET    /api/report/{session_id} — returns the full session report JSON
DELETE /api/session/{session_id}— cleans up the session

Requirements:
- Sessions stored in a Python dict (no database needed)
- Session object must track: role, interview_type, current_question,
  question_number, total_questions, difficulty, qa_records
- Difficulty adapts after each answer: score > 7 → hard, score < 4 → easy,
  else medium
- num_questions must be configurable (slider range 3-15, default 5)
- Skipped questions get all scores set to 0 and a "skipped" flag
- Import from agents: generate_question, evaluate_answer, generate_feedback,
  generate_final_summary, InterviewSession, adapt_difficulty

WHY THIS PROMPT WORKS:
- Each endpoint is specified with exact signature and behaviour
- Business rules (difficulty thresholds, skip scoring) stated explicitly
- Import requirements prevent the model from inventing its own structure
